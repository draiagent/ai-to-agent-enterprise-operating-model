# 完整案例｜會議紀錄轉行動任務

版本：1.0.0｜教學模擬案例，無真實個資及實績主張。

## VAD：看懂現行工作

會議主持人確認紀錄；行政整理行動項目；專案負責人確認任務、負責人與日期；行政寫入任務系統；負責人核對。常見問題是漏項、猜測負責人及重複建立。

導入後由 Agent 準備任務草稿與寫入，人保留核准與例外處理。

## VAC：MEETING-001／1.0.0

負責人：專案負責人。引用規則：DC-MEETING-001／1.0.0。

| 主欄 | 規格 |
|---|---|
| Goal | 將已確認會議紀錄中的行動事項轉成任務草稿，核准後建立到指定專案；不發送外部郵件 |
| Context | 會議 ID、已確認紀錄、段落編號、可用人員名單及指定專案 ID；紀錄須有版本與確認狀態 |
| Action | 擷取事項，附原文段落；列出草稿；取得核准；檢查去重鍵；建立任務；回讀並產生結果清單 |
| Acceptance | 原文明示事項均被建立或列為待確認；無猜測負責人、無未核准寫入、無重複；每項有來源及結果證據 |

## DC：DC-MEETING-001／1.0.0

適用 VAC：MEETING-001／1.0.0。核准人：專案負責人。

| 主欄 | 規則 |
|---|---|
| Decision | 分類為可準備草稿、待確認、可寫入或停止 |
| Criteria | 紀錄已確認；行動內容明確；人員可唯一對應；日期具體；核准內容與將寫入內容一致 |
| Authority | A2；唯讀會議資料；僅可在指定專案建立已核准任務；核准限該批內容且有效 24 小時；不修改或刪除既有任務 |
| Escalation | 缺負責人、日期歧義、資料衝突或核准過期則找專案負責人；寫入失敗先查狀態，確認未寫入才允許重試 1 次；10 分鐘未完成則停止並交接 |

24 小時、1 次、10 分鐘是本教學案例的示範設定，企業導入時需依工作需求核准。核准綁定批次內容摘要或雜湊；內容改動後需重新核准。執行端應檢查專案範圍與核准狀態，不能只讀取文字指令。

## 六環節走一遍

| 環節 | 本案行為 |
|---|---|
| Goal | 建立可追溯且已核准的會議任務 |
| Context | 讀取確認紀錄、人員對照、專案及 DC |
| Reason | 擷取 P01、P02，列出缺漏與草稿 |
| Decide | P01 等待核准；P02 交人補充；無核准不寫入 |
| Action | 模擬核准 P01 後，以會議 ID＋段落 ID 作去重鍵建立任務 |
| Evaluate | 回讀內容；確認 P01 正確建立、P02 已列待確認，檢查無重複及越權 |

模擬驗收紀錄：P01 對應 DEMO-T001；P02 保留待確認；狀態為「本批處理完成，仍有一項待人工確認」。不得把它寫成所有業務事項已完成。

技術實作應保存去重鍵到任務系統可查詢欄位，或另設執行紀錄；重跑時先查現有任務。寫入狀態不明時停止，不盲目重試。因本案無刪除權，錯誤任務由人更正。

## 如何量測價值

先記錄人工流程每次從確認紀錄到任務完成登錄的處理分鐘數、漏項與重複數。試點採相同計算範圍，納入核准與返工時間。資料足夠後才能報告變化；本案例沒有實測改善百分比。
