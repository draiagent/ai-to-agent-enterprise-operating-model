# 一致性審查與定版紀錄

版本：1.0.0｜審查日期：2026-09-22

範圍：使用者提供的多輪介紹、收斂版與統一版。本次為概念、文件與範本一致性審查，不是第三方認證或真實企業試驗。

| 前文問題 | 本版處理 | 理由 |
|---|---|---|
| Goal 與 Intent 並列 | 統一為 Goal | 避免同一目的重複命名 |
| Context 被簡寫為知識 | 固定為上下文 | 保留當次輸入、狀態與限制 |
| KPI 與 Evaluate 混用 | VAC 使用 Acceptance；Evaluate 使用驗收標準及 KPI | 指標不是驗證活動，也不涵蓋所有必要條件 |
| 治理有時是流程一步 | 全程治理，具體行動前仍設控制點 | 制度與控制點各有位置 |
| VAC 六格、四格反覆變動 | 固定四主欄，另有文件管理資料 | 減少欄位，保留可追溯性 |
| VAC 與 DC 被稱為完全解耦 | 分工並以文件 ID、版本互相引用 | 任務必須綁定有效的決策規則 |
| DC 之後又選自主權 | A1–A4 寫入 DC.Authority | 避免雙重授權來源 |
| A4 以多 Agent 定義 | 改為 Orchestrated Autonomy／流程自主 | Agent 數量與自主權是不同問題 |
| A4 才出現人治理 | 所有等級都受治理 | A1 草稿仍涉及資料與責任 |
| 自主權呈現必經升級階梯 | 各任務依風險與需求選級 | A2 可作為長期適當配置 |
| LLM、MCP 等被固定塞入單一環節 | 改為跨環節實作資源 | 模型、產品、協定、技能不能視為同種元件 |
| Promptless 被當成自動結果 | 明定需要規格載入與實作控制 | 文件不能自行接通工具 |
| 閉環可能被理解為無限改善 | 增加停止、重試與變更邊界 | 不允許自行擴權或改目標 |
| 87%、提高 12% 等數字像實證 | 移除未驗證效能數字 | 示例與實測結果必須區分 |
| 乘法公式看似可計算 | 移除，保留 6・3・4・1 記憶法 | 無量化定義不作科學公式 |
| A0–A5 與五階段轉型重複 | 主文只保留 A1–A4 | 不再增設平行成熟度框架 |

本版確認：README、完整說明、教學版、範本與案例採用相同定義；案例明示 A2，不宣稱企業實績；DC 有停止規則；VAC 引用 DC；產品案例與方法論分開維護。

不作主張：這套分類是全球標準、圖卡本身就是可執行程式、型別正確就代表判斷正確、信心分數等於授權、多 Agent 必然更成熟。
