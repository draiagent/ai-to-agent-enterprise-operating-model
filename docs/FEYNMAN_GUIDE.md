# 費曼學習版：把 Agent 當成需要交接的新同事

版本：1.0.0｜2026-09-22

公司來了一位能力很強的新同事。主管只說「幫我把工作做好」，他仍然不知道資料在哪、能做哪些決定，以及怎樣才算完成。Agent 也需要同樣的交接。

**第一步，VAD 看懂工作。** 先畫出誰提供資料、誰判斷、誰執行、出了問題找誰。像是讓新同事先看懂部門怎麼運作。

**第二步，VAC 定義工作。** 寫清楚要交付什麼、使用哪些資料、採取哪些行動、怎樣驗收。像是一張清楚的工作單。

**第三步，DC 管住決策。** 訂好哪些情況能做、哪些要核准、哪些要停下來。像是主管交代的授權規則。工作單必須連到對應的規則，不能各寫各的。

接著才決定讓這位同事做到哪裡：A1 幫我想；A2 我核准後執行；A3 在單一任務內自主；A4 在授權流程內調度任務。人多不代表權力大，多個 Agent 一起做草稿仍可能只有 A1。

實際工作依六個問題展開：要完成什麼？需要知道什麼？如何分析？採取哪個允許的選項？如何執行？有沒有符合標準？這就是目標、上下文、推理、決策、行動、驗證。

例如會議結束後，要把確認過的事項建立成任務：Agent 先整理草稿，主管核准後才寫入任務系統。負責人不明就標記待確認，不能自己猜；寫入失敗先查有沒有部分成功，不能一直重送。

最後，不只看任務有沒有建立，還要看有沒有漏項、錯誤或重複。節省多少時間則另外量測。這樣才知道工具成功與企業價值有沒有同時達成。

請用自己的工作回答五題：

1. 要交付哪個具體結果？
2. 哪些資料不足時必須停下來？
3. 哪些行動一定要有人核准？
4. 出錯後誰負責處理？
5. 用什麼證據確認已完成？

若無法回答，先補好工作設計。**企業導入的重點，是讓工作有目標、決策有邊界、結果有證據。**
